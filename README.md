# URL Shortener

A full-stack URL shortener built with **React (Vite)**, **NestJS**, **PostgreSQL**, **Docker**, and **Nginx**.

---

# Prerequisites

Before running the project, ensure you have the following installed:

* Docker
* Docker Compose

---

# Environment Variables

The project requires three `.env` files.

## 1. Root Directory

Create a `.env` file in the project root:

```env
DB_USER=postgres
DB_PASS=<your_database_password>
DB_NAME=url_shortner
```

---

## 2. Backend

Create a `.env` file inside the `backend` directory:

```env
# Use localhost when running the backend without Docker.
# Docker Compose automatically overrides this to "postgres".
DB_HOST=localhost

#DB_HOST=postgres

DB_PORT=5432
DB_USER=postgres
DB_PASS=<your_database_password>
DB_NAME=url_shortner

JWT_SECRET=<generate_a_long_random_secret>
JWT_EXPIRY=7d

BASE_URL=http://localhost:3000
PORT=3000
```

> **Note:** When running with Docker Compose, `DB_HOST` is automatically overridden to `postgres`, so you do not need to modify this file.

---

## 3. Frontend

Create a `.env` file inside the `frontend` directory if required by your frontend configuration.

---

# Running the Application

From the project root, build and start all services:

```bash
docker compose up --build
```

Docker Compose will build and start:

* React Frontend
* Nginx
* NestJS Backend
* PostgreSQL

---

# Accessing the Application

The frontend is available at:

```
http://localhost:5173
```

Only the frontend is exposed to your machine.

The backend and PostgreSQL are intentionally **not exposed** and communicate internally through Docker's private network.

---

# Using Short URLs

After creating a shortened URL, access it using:

```
http://localhost:5173/s/<code>
```

Example:

```
http://localhost:5173/s/abc123
```

Where:

* `code` is the unique short code generated by the backend.
* Nginx forwards the request to the backend.
* The backend looks up the original URL in PostgreSQL.
* If found, it responds with an HTTP redirect to the original destination.

---

# Project Architecture

The application follows a **reverse proxy architecture**, where **Nginx** serves as the single public entry point.

Rather than exposing the backend directly, Nginx receives every incoming request and routes it to the appropriate service.

```text
                    User
                      │
          http://localhost:5173
                      │
                      ▼
                Nginx (Frontend)
        ┌─────────────┼─────────────┐
        │             │             │
        ▼             ▼             ▼
   React SPA      NestJS API   Short URL Redirect
      (/)           (/api/*)      (/s/:code)
                        │
                        ▼
                  PostgreSQL
```

## Components

### Nginx

* Serves the React production build.
* Acts as a reverse proxy.
* Routes incoming requests:

  * `/` → React application
  * `/api/*` → NestJS API
  * `/s/:code` → URL redirection endpoint

---

### React (Vite)

* Provides the user interface.
* Served as static files by Nginx.
* Uses relative API paths (`/api/...`) instead of directly communicating with the backend.
* Handles client-side routing.

---

### NestJS

* Exposes REST API endpoints under `/api`.
* Contains all application business logic.
* Creates shortened URLs.
* Handles requests to `/s/:code` by retrieving the original URL and returning an HTTP redirect.

---

### PostgreSQL

* Stores application data, including shortened URLs.
* Is accessible only from the backend through Docker's internal network.

## Redirecting a Short URL

```text
Browser
    │
GET /s/abc123
    │
    ▼
Nginx
    │
    ▼
NestJS
    │
Looks up "abc123"
    │
    ▼
PostgreSQL
    │
Returns HTTP 301/302 Redirect
    │
    ▼
Browser navigates to the original URL
```

# Why This Architecture?

* **Single public entry point** – Only Nginx is exposed externally.
* **No CORS issues** – The browser communicates with a single origin while Nginx proxies requests internally.
* **Backend isolation** – The backend and database remain private inside Docker's internal network.
* **Separation of concerns** – Each service has a dedicated responsibility:

  * Nginx handles routing and static assets.
  * React manages the user interface.
  * NestJS contains the application logic.
  * PostgreSQL manages persistent storage.
* **Production-ready design** – This architecture scales well and can be extended with HTTPS, load balancing, caching, logging, and monitoring without significant application changes.
